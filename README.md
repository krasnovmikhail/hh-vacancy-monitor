
# Документация проекта: HH.ru Vacancy ETL & Automated Alerting System

## 1. Описание проекта

Высокопроизводительный и отказоустойчивый ETL-пайплайн для мониторинга рынка труда на платформе HeadHunter (HH.ru). 
Система осуществляет автоматический сбор, дедупликацию, хранение вакансий в базе данных PostgreSQL и рассылку уведомлений о подходящих вакансиях и статусах работы в Telegram.

## 2. Архитектура и стек технологий

* **Язык разработки:** Python 3.11+
* **База данных:** PostgreSQL
* **Ключевые библиотеки:** `requests`, `psycopg2-binary`, `pandas`, `python-dotenv`, `schedule`
* **Контейнеризация:** Docker, Docker Compose

### Структура файлов проекта

* **`config.py`**: Настройки фильтров, списки поисковых запросов и регионов.
* **`api.py`**: Взаимодействие с HH API, авторизация OAuth и кэширование токена.
* **`db.py`**: Подключение к PostgreSQL, SQL-запросы, создание и структура таблиц.
* **`notifier.py`**: Отправка сообщений и алертов в Telegram с HTML-разметкой.
* **`main.py`**: Главный скрипт сборки, дедупликации и анализа вакансий.
* **`scheduler.py`**: Планировщик периодического запуска.
* **`.env`**: Переменные окружения, секреты и ключи доступа.
* **`token_cache.json`**: Локальный кэш OAuth-токена HH API.
* **`Dockerfile`**: Инструкция сборки Docker-образа.
* **`docker-compose.yml`**: Оркестрация контейнеров приложения и базы данных.

## 3. Схема базы данных PostgreSQL

Пайплайн использует MD5-хэширование содержимого вакансий для определения изменений состояния (дедупликация и история изменений).

### Таблицы базы данных

1. **`vacancies`** — основная таблица актуального состояния вакансий.
* **Поля:** `vacancy_id`, `title`, `salary_from`, `salary_to`, `salary_currency`, `experience`, `work_formats`, `url`, `content_hash`, `is_active`, `published_at`, `updated_at`.


2. **`vacancy_skills`** — ключевые навыки, связанные с вакансией.
* **Поля:** `vacancy_id`, `skill_name`.


3. **`pipeline_runs`** — журнал запусков ETL-процесса для аудита.
* **Поля:** `run_id`, `start_time`, `end_time`, `total_processed`, `new_count`, `updated_count`, `archived_count`, `duration_seconds`.


4. **`vacancy_changes_log`** — история логических изменений вакансий.
* **Поля:** `vacancy_id`, `field_changed`, `old_value`, `new_value`, `changed_at`.


## 4. Конфигурация и настройка

### Переменные окружения в файле `.env`

```env
DB_HOST=localhost
DB_PORT=5432
DB_NAME=hh_vacancies
DB_USER=postgres
DB_PASSWORD=your_password

CLIENT_ID=your_client_id
CLIENT_SECRET=your_client_secret

TELEGRAM_BOT_TOKEN=your_bot_token
TELEGRAM_CHAT_ID=your_chat_id

```

### Настройка фильтров в `config.py`

```python
HOT_VACANCIES_ALERT_ENABLED = True
HOT_VACANCY_MIN_SALARY = 150000
FILTER_EXPERIENCE = ['От 1 года до 3 лет', 'Нет опыта']
FILTER_WORK_FORMATS = ['Удаленная работа']
FILTER_MUST_HAVE_SKILLS = ['SQL', 'Python']

```

**Примечание:** Если значение какого-либо параметра фильтра установлено как `None`, данный фильтр автоматически игнорируется при обработке.

## 5. Особенности и отказоустойчивость

* **Гарантия фиксации аудита:** Использование блока `try...finally` гарантирует, что даже при принудительном завершении процесса (`Ctrl+C`) или сетевом сбое статистика по фактически обработанным данным фиксируется в таблице `pipeline_runs` и отправляется сводкой в Telegram.
* **Кэширование OAuth-токена:** Токен HH API сохраняется в файл `token_cache.json` и обновляется только по истечении срока действия, исключая блокировку со стороны API за частые запросы авторизации.
* **Форматирование сообщений:** Уведомления отправляются с использованием HTML-тегов (`<b>`, `<i>`, `<a>`), что предотвращает ошибки парсинга из-за спецсимволов в текстах вакансий.
* **Защита от превышения лимитов:** Предусмотрены паузы между запросами и корректная обработка ответов API при превышении лимитов (Rate Limits).

## 6. Инструкция по запуску

### Запуск в локальном окружении Python

1. **Установка зависимостей:**
```bash
pip install -r requirements.txt

```


2. **Однократный запуск:**
```bash
python main.py

```


3. **Запуск по расписанию:**
```bash
python scheduler.py

```



### Запуск в контейнере Docker

1. **Сборка и запуск контейнеров в фоновом режиме:**
```bash
docker compose up -d --build

```


2. **Просмотр логов приложения:**
```bash
docker compose logs -f bot

```


3. **Остановка сервисов:**
```bash
docker compose down

```
